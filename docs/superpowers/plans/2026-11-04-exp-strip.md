# EXP Strip Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a passive, screen-reading EXP tracker overlay for MapleStory Classic: a compact always-on-top strip with per-map EXP/hour history, shipped as `ExpStrip.exe`.

**Architecture:**
- A 1 Hz worker thread does the reading:
  1. Captures the game's client area from the desktop (`mss`).
  2. Locates the status bar and minimap by multi-scale template matching.
  3. Reads digits with glyph templates and the map name with Windows OCR.
  4. Validates the readings and feeds them to a pure `Tracker`.
- The `Tracker` produces stats and finished visits. A CSV `VisitStore` persists the visits.
- A PySide6 strip, spots panel and tray icon display everything.
- All game-facing code is limited to user32 window queries plus desktop capture.

**Tech Stack:**
- Python 3.12 (`py -3.12`)
- PySide6, opencv-python, numpy, mss, winsdk, pywin32
- pytest
- PyInstaller

**Spec:** `docs/superpowers/specs/2026-11-04-exp-tracker-design.md`

## Global Constraints

- Never call `OpenProcess`, `ReadProcessMemory`, `SetWindowsHookEx`, `SendMessage`/`PostMessage` to the game, or `SetForegroundWindow` on the game. Do not inject or hook anything.
- Allowed game-window calls are limited to: `EnumWindows`, `FindWindow`, `GetWindowText`, `GetClientRect`, `ClientToScreen` and `IsIconic`.
- Pixels come only from desktop-region capture (`mss`), never from capturing the game window or process.
- No network calls of any kind. No admin rights.
- Exe, process and window name: `ExpStrip` / `ExpStrip.exe`. No words like hack, bot or cheat anywhere in names or UI.
- Every overlay window calls `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)` (`0x11`).
- Capture rate is about 1 Hz. The capture and read loop is never on the UI thread.
- Game window title: a case-insensitive substring match, default `MapleStory`, configurable in `settings.json`.
- OCR language: `en-US`, requested explicitly.
- Data lives in `data/` next to the exe (the project root when run from source):
  - `data/visits.csv`: UTF-8 with BOM, append-only. Columns: `date, map_full, spot, start_time, end_time, active_seconds, exp_gained, level_start, level_end`.
- Tracking thresholds:
  - Idle after 120 s with no EXP change.
  - Visits with under 60 s of active time are dropped.
  - EXP/hour shows `—` until 60 s of active time.
  - "5 min" uses a 300 s wall-time window.
  - The in-progress visit is flushed every 60 s.
- Strip look:
  - Cream pill `#fbf7ef`, about 560×60 px, orange level block and accents `#ff7a3d`, emphasized value `#e2581c`, muted text `#7d7468`, track `#eadfcd`.
  - Value order: EXP/hour, Level up in, 5 min, Session. Buttons: ⏸ and ☰.
  - Reference: `docs/reference/mockup-strip-with-history.html`.
  - Must not resemble `docs/reference/prior-art-other-tracker.png`.
- Status strings (exact):
  - `Waiting for game…`
  - `Can't read EXP — is the status bar visible?`
  - `Paused`
  - `Game not visible — use windowed mode`
- UI text is English. Tray menu items: `Lock (click-through)` / `Unlock`, `Pause` / `Resume`, `Open data folder`, `Quit`.

## Review Focus

1. **Covered digits.** The status bar is briefly covered (cursor, a dragged game window, a chat popup) and one frame misreads. That frame must be ignored: no EXP jump and no negative spike. Test owned by Task 3.
2. **Level-up with unknown requirement.** The tracker starts just before a level-up, so no requirement has been learned at the old level. The gain must not go negative or explode. Count only `exp_now` for that tick. Test owned by Task 4.
3. **Game closed or minimized mid-session.** Readings are `None` for many minutes. No active time accrues, there is no crash, and the visit continues when the game returns. Test owned by Task 4.
4. **Map name flicker.** A single-frame OCR misread of the map name must not start a new visit. Test owned by Task 3.
5. **Map names containing commas or quotes** must round-trip through `visits.csv` intact. Test owned by Task 5.

### Task 3: Reading model, EXP text parsing, map normalization, and validation

**Files:**
- Create: `expstrip/reading.py`
- Test: `tests/test_reading.py`

**Interfaces:**
- Produces:
  - `MapName`: frozen dataclass with `region: str` and `map: str`.
    - Property `full -> str`: `f"{region} : {map}"`, or just `map` if `region` is empty.
  - `Reading`: frozen dataclass with `level: int`, `exp: int`, `pct: float` and `map: MapName | None`.
  - `parse_exp_text(text: str) -> tuple[int, float] | None`. Accepts `"114,698 [26.78%]"`, with whitespace tolerated. Returns `None` on anything malformed.
  - `normalize_map_name(lines: list[str]) -> MapName | None`. Handles three inputs:
    - The collapsed form: one line, `"Victoria Road : Kerning City Pharmacy"`, split on the first `:`.
    - The expanded form: two lines, `["Victoria Road", "Kerning City"]`.
    - A single line with no `:`, which gives region `""`.

    Before splitting, it strips the text and collapses repeated spaces. Empty input gives `None`.
  - `ReadingValidator()`, with `feed(level: int | None, exp_pct: tuple[int, float] | None, map_name: MapName | None) -> Reading | None`.
    - It returns a `Reading` only when the (level, exp, pct) triple is identical in 2 consecutive feeds and is consistent.
      - Consistent means `pct` agrees with `exp / requirement` within 0.02 percentage points, where `requirement` is the one last learned at that level. If none has been learned, it is accepted.
      - `requirement` is learned as `exp / (pct/100)` from accepted readings with `pct >= 1.0`.
      - Until 2 consecutive feeds agree, it returns `None`.
    - Map handling: the returned `map` is the last map name seen in 2 consecutive feeds. A `None` map leaves the previous accepted map unchanged.
    - Method `requirement(level: int) -> int | None` exposes the learned value.

### Task 4: Tracker (EXP math, idle, pause, visits)

**Files:**
- Create: `expstrip/tracker.py`
- Test: `tests/test_tracker.py`

**Interfaces:**
- Consumes: `Reading`, `MapName` (Task 3); `ReadingValidator.requirement` is *not* used. The tracker learns its own requirement per level the same way: `round(exp / (pct/100))`, only when `pct >= 1.0`, keeping the latest value.
- Produces:
  - `Visit`: dataclass with these fields:
    - `map: MapName`
    - `start: float`, `end: float` (epoch seconds)
    - `active_seconds: float`
    - `exp_gained: int`
    - `level_start: int`, `level_end: int`
  - `Stats`: dataclass with these fields:
    - `level: int | None`, `pct: float | None`
    - `map: MapName | None`
    - `exp_per_hour: float | None`
    - `level_up_in: float | None` (seconds)
    - `last5: int`, `session: int`
    - `paused: bool`
  - `Tracker(now: float, on_visit_closed: Callable[[Visit], None], idle_after: float = 120, min_visit: float = 60)`
    - `update(reading: Reading | None, now: float) -> None`
    - `pause(now) -> None`, `resume(now) -> None`
    - `close(now) -> None`: closes the current visit, e.g. on exit.
    - `stats(now: float) -> Stats`
    - `current_visit_snapshot(now) -> Visit | None`: used for the periodic flush.

**Rules (from the spec, decided):**
- **Gain per accepted reading:**
  - Same level: `exp - prev_exp`. This may be negative (death).
  - Level +1 with a known requirement at the old level: `(req_old - prev_exp) + exp`.
  - Level +1 with an unknown requirement: `exp`.
  - Any other level change: gain 0. Re-baseline.
- **Active time** uses the pending-idle scheme. Time between consecutive non-`None` readings goes into `pending`. When the EXP value changes, `pending` is committed to `active` if `pending <= idle_after`; otherwise it is dropped. `stats()` counts the uncommitted `pending` only if `<= idle_after`.
- Time across a `None` gap is never accrued. After any `None`, the next real reading starts a fresh interval (`dt = 0`) and only re-baselines the time, not the EXP. Its gain still counts.
- **Pause:** no time accrues and gains are ignored. On resume, the next reading only re-baselines.
- **Visit lifecycle:**
  - The first accepted reading with a map opens a visit.
  - A different `reading.map` closes it at `now` and opens a new one.
  - Closed visits with `active_seconds < min_visit` are not emitted.
- **Stats:**
  - `exp_per_hour` = visit gain ÷ visit active hours, `None` if visit active < 60 s.
  - `level_up_in` = `(req_now - exp) / rate_per_second`, using the visit rate. Fall back to the session rate (session gain ÷ session active) if the visit rate is `None`. `None` if no rate, the rate is ≤ 0, or the requirement is unknown.
  - `last5` = sum of gains with timestamp in `(now-300, now]`.
  - `session` = sum of all gains.

### Task 7: Anchor templates, glyph templates, and the digit reader (requires Task 1 fixtures)

**Files:**
- Create: `expstrip/vision/glyphs.py`, `expstrip/vision/anchors.py`, `tools/extract_templates.py`, `expstrip/templates/` (PNG assets: `anchor_exp.png`, `anchor_lv.png`, `anchor_minimap_collapsed.png`, `anchor_minimap_expanded.png`, `exp/<char>.png`, `level/<digit>.png`)
- Test: `tests/test_vision.py`

**Interfaces:**
- Produces:
  - `anchors.Match`: frozen dataclass with `x: int`, `y: int`, `scale: float` and `score: float`. `x` and `y` are the top-left of the match in frame pixels.
  - `anchors.find(frame: np.ndarray, template: np.ndarray, scales: Iterable[float] = np.arange(0.6, 2.01, 0.05), min_score: float = 0.8) -> Match | None`. Uses `cv2.matchTemplate` with `TM_CCOEFF_NORMED` on grayscale.
  - `glyphs.GlyphSet.load(folder: Path) -> GlyphSet`. The character is the filename stem; `comma`, `dot`, `pct`, `lbr` and `rbr` map to `,` `.` `%` `[` `]`.
  - `glyphs.read(crop: np.ndarray, gs: GlyphSet, scale: float, mode: Literal["exp", "level"]) -> str`. The steps are:
    1. Resize by `1/scale`.
    2. Binarize. For `"exp"` mode, keep white text (V > 170, S < 60 in HSV). For `"level"` mode, keep the light glyph on the orange tile (V > 200, S < 80) inside orange tile regions.
    3. Split into glyphs by empty columns.
    4. Classify each glyph by best `TM_CCOEFF_NORMED` against the same-height templates.
    5. Concatenate.

    Glyphs scoring below 0.6 produce `"?"`, which makes downstream parsing fail safely.
  - `templates_dir() -> Path`: handles the PyInstaller `sys._MEIPASS`.

**Interfaces:**

  - `layout.Rect`: `x`, `y`, `w`, `h` (int).

**Interfaces:**
